# Design

The installer is a thin shell entrypoint with modular typed Python orchestration, bounded filesystem/network/process interfaces and durable owned checkpoints. Core runtime, installer runtime and auxiliary component environments are distinct. Official pinned Hermes uses its PM-managed Python3.14; dependencies never downgrade the host or core globally. Source/license/capture/schema templates are executable inputs in contracts/, independent of current planning.

## Core service and lifecycle

Resolve core-only Agent/runtime prerequisites without graphical preflight. For adoption verify the selected owner, current HOME/HERMES_HOME, existing Codex credential references, source/PM executable/lock, units/ports and journal. Preserve data/auth/memory and unrelated services. Stage reviewed official upstream bytes under owned paths, then run only fixed `hermes serve --host 127.0.0.1 --port <owned validated loopback port>` as the selected unprivileged owner with sanitized environment. Browser input cannot select command, port, filesystem path, unit or credential. Verify service readback, private authenticated health/chat/stop/history/restart, failure recovery and rollback. Existing-target migration and fresh installation have distinct acceptance.

The normal `hermes-installer install` and `resume` entrypoints begin with the fixed headless core stage; non-root entrypoints return the exact root-owned `core-service install` or `core-service resume` handoff without doing privileged work themselves. Desktop is excluded from new defaults and remains a capability benchmark. After the canonical admin HOME exists, core setup invokes the fixed offline `import-bundled` Resources command as admin with the pinned Hermes source and PM Python; its bounded native read-back is reported as materialized/discovered only, never as functional use or full Resources acceptance. Existing `SOUL.md` and auth references remain preserved.

Install/resume/rollback is an actual finite reviewed root adapter with exact source/PM/unit/config/token/owner/loopback/journal checks, never a placeholder callback or general shell authority. Stage into a new owned generation, verify full bytes/dependencies, then atomically switch pointers; interruption retains prior state and exact resume. Backup/compatible restore, update, uninstall, restart and reboot require effects and failure proof.

## Private engine bridge

Use official `hermes serve` → `hermes_cli.web_server` → private authenticated `/api/ws` → `tui_gateway.ws`. Do not start the separate API-server listener or forward the backend router wholesale. Pin actual schemas/events for session.create, prompt.submit, history/replay, interrupt and session.resume. Derive principal → opaque conversation → official stored_session_id server-side. Live session_id is generation-local: after restart invalidate the stale ID, privately resume the exact stored session, validate result/current generation and atomically bind the fresh ID. Deny unknown/malformed/cross-owner resume; never silently create substitute history. Backend credentials remain protected server references.

## Capability ports and Resources

Core first, then one actual capability at a time; core plus one useful port enables responsive UI while further ports continue. Each row in requirements/current-scope.json maps exact component identity/aliases, task and substantive verification. Preserve full server-owned Bots rooms/groups/roster/orchestration/relay with durable worker state; renderer ui_meta is not parity. Bind approvals to exact owner/run/action/nonce/deadline. Skills/plugins/MCP need complete helpers/assets/license/provenance and selected harmless actual discovery/use. Messaging/jobs/webhooks require account enrollment and fresh background grants, not a parser or catalog. Files/artifacts require opaque owned IDs, size/type/root/content grants and safe preview. Browser tools require constrained owner sessions and retained browser sandbox. Settings/provider/model/account adapters are individual secure owner functions, never raw configuration routers. Voice has explicit permission/account/cost/device/background limitations. Native tray/hotkeys/HUD/OS-dialog conveniences need a distinct browser alternative or pending status.

Full Resources preserves all208 original source identities: Jarvis is the single user-facing identity,207 internal identities remain with provenance/inheritance/tool permissions/skills/assets and real delegated dispatch. Definitions/materialization differ from native discovery, authentication, functional effects and enablement. Use a complete individual capability matrix, not only representative class tests. Retain one automatic memory owner per profile, cross-session retrieval proof and actual process/tool/filesystem policy; profile names alone are not isolation. Original GLM-5.2 artifact/ARM64 engine/performance and delegate-used Coral TPU obligations remain separately gated. HA live configuration is deferred.

## Responsive Jarvis and public authorization

Original restrained dark/cyan presentation follows actual functionality: accessible contrast/focus/keyboard, real mobile composer, truthful busy/error states, reduced motion, stop/history/reconnect and independently owned conversations. Owner/family identities and tool/memory grants are explicit. Conversation ownership does not claim shared-home/tool/global-memory isolation. Unproven private/family capabilities remain unavailable.

Preserve owned Cloudflare Access OTP/binding and hostname. New wizard hostname starts blank; securely collect scoped setup token/reference, select owned account/zone and journal automatic idempotent tunnel/DNS/Access/allowed-email setup. Preserve unowned conflicts; activate ingress only after protection and loopback validation. Management token is setup-only; runtime uses protected dedicated tunnel token file. Gateway validates JWT algorithm/signature/issuer/audience/time/principal before every asset/input/byte and enforces same-origin CSRF plus server ownership. No public raw RPC/shell/arbitrary URL/filesystem/backend management.

At initial turn authorization retain original admitted JWT deadline, monotonic acceptance and exact principal/conversation/run. Ceiling is min(original JWT expiry, acceptance+600s, stricter backend deadline). Each independently issued lease expires within30s. Before expiry a new protected nonce heartbeat may issue a distinct lease, with <=5s fresh independent ingress revocation witness at every byte and <=4s SSE segment. Cached proof cannot restamp/renew old proof, expired lease cannot revive the run, and later JWT only narrows original ceiling. Missing/refused/stale witness denies bytes and cancels exact owned turn within freshness bound. Prove actual >30s continuation and all expiry/revocation/replay/cross-owner denials on Pi.

## Owned graphical cleanup and final review

Desktop/Xpra/native presentation is excluded from active installation. Remove only journal/inventory-verified owned units/processes/dedicated AppDir/source/guards/helpers/config after private independent core and replacement protected public owner chat, expiry/revocation and restart/recovery proof. Preserve HOME/auth/PM/Resources/recovery backups/shared tunnels/unrelated services. Restore shared changes only against verified backups/current object; leave unknown/shared conflicts pending and never blanket apt purge or strand existing URL.

Zero extra metered budget/private routing applies to every dispatch, retry, fallback, background job, extraction and embedding. No secrets in source/argv/logs/evidence/browser storage or duplicated profiles; no huge download, paid action, reimage/format, unrelated replacement or outbound test messaging without applicable authorization. Prestart OpenViking sanitized; disable unreviewed lazy installs; preserve TLS and browser sandbox.

Full release requires actual end-to-end Pi/account/hardware/capability/denial/recovery evidence and reconciled source/spec behavior. Tests/fixtures/previews/servers/validators run only on the identified Pi via root browser. Local source/spec editing and Git are allowed. Final usage/operations/troubleshooting/contributor/AI documentation follows genuine qualification; no stable/parity/Resources acceptance from sources, configuration, fixture, health or one chat.
