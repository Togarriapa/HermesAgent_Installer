# Protected homelab plugin effects

The pinned Authentik, Cloudflare, and host operations manifests are hashed at
load time against their vendored source revision. Native tools call only the
protected `plugin_effects` resolver. It must choose a root-enrolled action,
target, account, credential reference, recipient, operation, generation,
argument schema, size/deadline bounds, confirmation policy, and idempotency
policy. The native process does not supply enrollment or target IDs.

Cloudflare route names were checked against its official API reference for
[DNS record retrieval](https://developers.cloudflare.com/api/resources/dns/subresources/records/methods/get/),
[DNS record overwrite](https://developers.cloudflare.com/api/typescript/resources/dns/subresources/records/methods/update/),
[tunnel configuration](https://developers.cloudflare.com/api/resources/zero_trust/subresources/tunnels/subresources/cloudflared/subresources/configurations/),
and [tunnel connections](https://developers.cloudflare.com/api/resources/zero_trust/subresources/tunnels/subresources/cloudflared/subresources/connections/).

`plugin_homelab_broker.build_plugin_homelab_effect_handlers` builds Authority
Service handlers from typed root-selected records. It checks the complete
action/grant/context/payload binding, resolves the vault reference as root,
and uses bounded verified-TLS HTTPS with no redirects. The Cloudflare
implementation addresses only the enrolled zone, DNS record ID, and tunnel
IDs for the three manifest hostnames. It reads a DNS record before updating
it, requires the returned record ID and hostname to match the owned record,
and refuses to adopt a conflict. A DNS write is reported as `ambiguous` until
a later separately authorized read reconciles its outcome. Tunnel service
routes are selected from protected host enrollment and unrelated ingress
rules are retained. The host operations broker receives only the fixed
enrolled physical target ID and one manifest-listed operation; the URL path
is generated by the handler and caller paths/commands/argv are not accepted.

Writes require a fresh root Authentik System membership check. Destructive
actions additionally consume an opaque, exact-payload trusted-human
attestation. Writes reserve durable idempotency state before external dispatch;
uncertain outcomes become terminal ambiguous records pending fresh readback.
No credential value is returned to the worker or included in result/audit
payloads. Authentik read actions use only the public root policy snapshot API;
alarm recipient enumeration additionally requires an explicit protected
recipient-ID list and fresh System membership. Missing account/target
enrollment, credential scope, recipient list, host effect resolver, or live
target proof leaves the affected action unavailable. The current protected
runtime has not yet integrated the selected-plugin resolver or enrolled any
account/host targets, so the source wrappers intentionally fail closed.
Fixture effects do not establish account or Raspberry Pi acceptance.
