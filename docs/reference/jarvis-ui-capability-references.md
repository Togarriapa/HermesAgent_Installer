# Jarvis / Hermes video reference matrix

Research notes for native Hermes Core with a custom responsive Jarvis UI. This document records evidence visible in available YouTube captions or selected original-player frames; it does not claim full-video viewing. Captions are auto-generated where noted, so technical terms may be imperfect. Video demonstrations belong to their creators and are not proof that a capability ships in Hermes.

## Evidence coverage

- 16 source IDs had exportable captions reviewed (15 long-form walkthroughs plus the 42-second `6Tb41ORADgs` promo/teaser).
- `KUvSzvFeZls` had no transcript; selected real frames only.
- Three Shorts (`6smKhzEXM_s`, `2NKpA6smfwg`, `V6kvapGV9qk`) had selected real frames/caption overlays only; no full transcript.
- No remote video was downloaded. Ad-only frames were excluded. Short / selected-frame evidence supports only what is actually visible at that instant.

## Mapping to a native Hermes Core + custom responsive UI

| UI/capability area | Evidence-backed design idea | Native/current gap to verify before implementation |
|---|---|---|
| Navigation | Start with actual Hermes concepts from `zCTK`: Chat, Sessions, Files, Models, Logs, Cron, Skills, Plugins, MCP, Channels, Webhooks, Pairing, Profiles. Add Tasks/Missions only if the core exposes a real task/mission model. | Confirm actual native API/state for every tab. Avoid dashboard-only shadow systems that invent task or agent truth. |
| Overview | Gateway/profile health, current tasks, recent activity and CPU/RAM/disk; add source-labeled model/token/cost, success/failure and retry summaries where the runtime can supply them (`Aqh`, `Ytpp`, `Iup`, `u7`). | Runtime metrics, per-agent accounting and success labels may not exist natively; mark unavailable instead of fabricating or estimating silently. |
| Mission/task workflow | Brief → team/target → review → execute; show plan/progress/current step, task owner, status, result, retry and approval boundary (`Ytpp`, `Iup`, `Aqh`). | Hermes native background task/mission semantics and cancellation must be verified; do not present custom orchestration as native. |
| Agent/workflow visualization | Optional linked capability/workflow graph with filterable nodes and clear status legend (`Acw`, `KUv`); a restrained orb/waveform can indicate voice state (`Acw`, `s3`, `ufPb`). | Graph nodes must represent registered capabilities only; mark third-party tools separately and do not imply that an integration is enabled. |
| Memory/personality | Profile/rules editor, sourced memory notes and an index/map for selective retrieval (`zCTK`, `h9`, `cQq`, `Iup`). | Show source and persistence boundaries; no claim of unlimited or automatically shared memory. |
| Voice | Separate input/STT and output/TTS provider, language/voice, wake-word, autoplay, streaming and interrupt controls; render idle/listening/transcribing/speaking/stopped state (`Aqh`, `Rqw`, `s3`, `ufPb`, `acs`, `u7`). | Native Hermes built-in voice settings/backend are not established by custom demos. Wake-word/always-listening and external voice providers must be opt-in and have explicit privacy/cost status. |
| Integrations / actions | Per-integration connection and capability status; draft/review/confirm for outbound email/calendar/browser/smart-home actions (`Rqw`, `O2`, `MeEZ`, `u7`). | Connectors and actuation require user-scoped authorization; never infer authorization from the video. The demos are not evidence of currently connected accounts. |
| Responsive behavior | Prefer compact cards, clear status colors with labels, collapsible navigation, and modal review steps over dense 3D-only control rooms. | Videos do not provide validated accessibility, keyboard, contrast, small-screen or performance results. Test these separately against the project’s actual design constraints. |

## Source limitations

Frames were selected captures, not full-frame inspection at every timestamp. Three Shorts do not have full captions. `KUvSzvFeZls` transcript export explicitly returned “No transcript available.” Captions are auto-generated and may mistranscribe product names. The reference demos cover different stacks (Claude Code, Telegram, cloud agents, third-party TTS/MCP/Home Assistant); only `zCTKDgETwUQ` directly demonstrates Hermes’ own management dashboard, while the other UI patterns are inspiration, not native capability evidence.
