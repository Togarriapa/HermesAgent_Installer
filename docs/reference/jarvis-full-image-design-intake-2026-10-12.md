## Highest-value design changes

1. **Make Overview hierarchy truthful and calmer.** Keep Jarvis as the sole user-facing MASTER and the central circular presence already authored in Overview. Put its actual state and a small number of real owner turn/activity readouts first; label source/time/window and show unavailable or unknown explicitly. Treat catalog relationships as static and event paths as event-backed. Avoid idle pulsing, fake audio amplitude, rotating orbits, synthetic “optimal/live” badges and unsupported system gauges.

2. **Make Projects and Knowledge useful at tablet/phone sizes.** The Kanban image’s four-column board and right-side ranked queue is a useful desktop pattern; on narrow screens, provide a single status-column selector or ordered task cards with 44px-class touch targets, clear empty/error states, and no sideways board as the only path. Keep the knowledge graph secondary to searchable/readable notes and links, with an equivalent list/detail navigation path and preserved note provenance. Verify keyboard/focus and the on-screen keyboard layout in the RootPi browser before deployment.

3. **Separate service-presence motion from real activity; support reduced motion.** Preserve the requested restrained orbital motion while an actual current service witness says Hermes is running and the Overview is visible. Stop it when that witness is stale/unavailable, the page is hidden, or the user requests reduced motion; static rings and a clear status label remain. Treat this slow ambient service-presence cue as distinct from working/listening/speaking state, audio-reactive motion, and Expert/Team flow: those require their own genuine current state or correlated event and must not be implied by the idle orbit. Keep labels and task text stationary. These are design recommendations, not a runtime review or implementation.
