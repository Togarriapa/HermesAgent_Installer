# Jarvis master-semantics overlay

The offline Resources package retains the pinned upstream 2.3.1 source declarations, revision, and tree unchanged. The installer applies `jarvis-master-semantics-v1` only while compiling the `hermes`, `orchestrator`, and `hermes-runtime` outputs. The artifact records the approved overlay commit, exact overlay digest, original declaration digests, baseline compiled prompt digests, and resulting effective prompt and bundle digests. The 396 skill cards and 208 source profile identities remain in the same single owned generation; this does not create selectable expert profiles or duplicate skill scans.

The overlay makes Jarvis the only user-facing MASTER, permits bounded OneShot work or a Jarvis-selected project/Kanban, and makes Orchestrator coordination optional. It describes selective internal expert/Team/Bundle research and draft collaboration, with proposed knowledge-base or skill changes returned for Jarvis review. Jarvis alone retains final user-facing decisions and external Write, Publish, Post, or Merge actions, subject to live native authorization. Task-start autonomy must be explicit and scoped; otherwise Jarvis asks and waits. These prompt/configuration statements grant no native tools, account, permission, or sandbox boundary. Native profile selection, tool intersections, and external-effect gates remain separate runtime work.

The overlay deliberately removes the mandatory six-section answer format and removes the Orchestrator's unconditional Kanban plugin dependency. The pinned response-contract skill and Epic Kanban plugin declarations remain present in the source inventory; neither is silently activated. Kanban and other non-skill effects remain unavailable until a reviewed native adapter is independently verified.

On the enrolled Pi, the existing pre-overlay generation is eligible for replacement only when root supplies the exact retained CAS archive SHA `f73463c641ac3744007ee8395b663802d5c916f59256fa8184ad2b4f5594b274` and the importer independently verifies its journal, full membership, and every byte. The importer stages the derivative in a private temporary directory and atomically exchanges it with the one visible generation path. The old generation moves outside `skills/` and is retained. The native loader must verify the complete new skill inventory; on failure, the importer atomically restores the old generation and keeps the new candidate outside `skills/`. Existing `SOUL.md`, config, memories, auth, user skills, and unrelated files are not rewritten.

No prompt adoption is performed by this overlay package step. Root's separately owned primary-prompt integration remains pending until native effective-prompt readback proves that the complete reviewed Jarvis block survives Hermes' normalization and truncation behavior.
