# Bootstrap and preflight

`./install.sh --help` and `./install.sh plan --json` run a read-only compatibility probe. The installer package itself uses only Python's standard library. `installer.example.json` is a secret-free starting point; create a private copy before editing it. Paths and selections are validated before handlers run.

The installer support gate currently accepts Debian/Raspberry Pi OS 11–13 and Ubuntu 20.04, 22.04, 24.04 or 26.04 on 64-bit ARM Linux when glibc 2.28+, an active systemd manager and the expected FHS directories are present. This is the installer's curated apt-oriented matrix; Hermes upstream lists Linux ARM64 more broadly but describes systems meeting those runtime conditions as likely to work. The development Mac is rejected for install and service-changing commands. Preflight reports observed facts. An absent graphical session, Coral device, or target account remains pending; it is never inferred from the requested target description.

The command runner takes argument arrays, resolves only fixed system-tool directories, rejects unreviewed executables and environment overrides, applies output/time limits, and kills surviving child processes on timeout. Its current allowlist only supports read-only probes; it is not a general process sandbox. The owned-state layer rejects symlink traversal and non-empty unowned roots, uses a process lock in an installer-owned root, and stores checkpoints in a private SQLite journal with full synchronous durability.

The CLI names are present, while component installation, adoption, generated services, update/rollback, provider and MCP operations, and target acceptance handlers remain in progress. A pending result means a handler or authorized target probe is not yet available; it does not mean the component is installed. Run `./install.sh plan --json` for the current read-only machine report; on a TTY, running `./install.sh` opens the guided action menu.

Protected service enrollment is a root-only transaction in `authority/bootstrap_enrollment.py`. First-snapshot creation is exposed only through `RootBootstrapProvisionOperation`, a separate root-local setup entrypoint; its socket adapter must supply kernel peer credentials and independently verified setup-session admission. It accepts only opaque artifact-receipt handles and a root-issued transaction handle. The `RootArtifactReceiptRegistry` mints durable random handles scoped to that setup transaction; `ArtifactStoreReceiptResolver` checks them against the protected artifact catalog and root CAS, then the transaction rehashes bytes while copying them into the root-owned content-addressed store. Root policy chooses service identity, separate 0700 home/work/data roots, paths, recipes, and complete catalog rows. The strict `service_generations` snapshot includes source, resource-job, remote-session, backend, body-recipe, scope-binding, and validator catalogs and uses the authority loader's UTF-8 canonical digest. A reviewed root-selected base authority can initialize the authority file in the same transaction. The durable journal records setup provenance and staged ownership. Recovery restores interrupted publication; `rollback(provision_receipt_handle, expected_generation_digest=...)` performs compare-and-swap rollback after failed health checks, preserves non-empty service data, and refuses changed ownership or artifact bytes. Existing accounts without the installer's root-owned identity marker and roots with foreign ownership block enrollment. The per-user worker socket does not expose first-snapshot provisioning.

Provisioning is deliberately two phase. A prepared first snapshot can establish the dedicated service identity, private roots, and source-artifact custody while publishing no runnable service records or worker effect rules. Activation requires a later root-selected generation with real package-manager/runtime and launcher receipts; source archive identity cannot stand in for executable identity. The immutable official Hermes archive is pinned at commit `7085fbf7753266fc4943c55ac04926186bc90005`, SHA-256 `592ac0b09a7130cf2f8166f039098ba4ed40fb91535c601a6a7e5b1fcf889d01`, 80,347,460 bytes, and Git tree `64e4a14da0e2f639a6977f90d6af07d93ea100c3`. The source catalog allows bounded acquisition up to 96 MiB compressed and 256 MiB expanded; an importer must still verify the complete archive, normalized tree, and root CAS receipt before minting a setup-scoped receipt handle. Focused canonical-generation, parser, fixed-verb, peer/admission, and pathless-receipt tests pass. Root-only Linux fixtures exercise disposable OS identity and root-owned artifact/service-root custody, symlink/foreign-root rejection, prepared→active publication, CAS health rollback, and interrupted commit recovery; they are skipped on this non-root host. No live account or protected authority file was changed.
