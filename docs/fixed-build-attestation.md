# Fixed source-build execution and output attestations

The root build handler accepts only the selected `process.start` envelope: enrollment ID, generation, one fixed Sol operation ID, and `parameters: {}`. `colibri-source-build-v1` selects `colibri-source-build:start`; `coral-cpython39-source-build-v1` selects `coral-cpython-build:start`. A worker cannot choose an executable, source/toolchain artifact, compiler flag, path, output name, or environment value.

`RootBuildExecutionService` resolves the protected profile and source, toolchain, and builder pins through the root artifact catalog. A root-managed build launcher must return terminal success, exact isolation readbacks, verified cleanup, an empty job cgroup, and a process identity bound to its root terminal record. A live PID or process-start receipt never counts as build completion.

The protected profile declares finite output constraints: relative path, file/tree kind, maximum bytes, executable role, and target facts. It does not pre-enroll compiled hashes. After terminal success the root rejects missing or unreviewed files/directories, symlinks, hardlinks, wrong ownership, and size-bound violations; it hashes each file and builds a canonical tree manifest. The Linux inspector independently checks ELF64/AArch64 format and dynamic dependencies against the enrolled toolchain sysroot, verifies Colibri's exact pinned `c/Makefile` and `c/setup.sh`, and requires an isolated root-managed CPython probe to establish version 3.9.25, nondebug SOABI, and glibc facts. Every observed fact is covered by the signed receipt.

Verified file bytes and complete output trees are copied into immutable root-owned CAS objects. The store writes and fsyncs the receipt before atomically advancing the target/generation index. An expiry or verification failure leaves the previous current receipt unchanged; unreferenced CAS objects may remain for safe garbage collection. The dynamic receipt binds service-generation digest, recipe/source/toolchain/builder pins, process identity and terminal-success record, output hashes/sizes/facts, and bounded log evidence. Its digest is issued after the build and is not a pre-enrollment fact.

`ContentAddressedBuildStore.resolve(profile)` rechecks the root signature, current generation, expiry, recipe pins, output constraints, and CAS bytes. `resolve_output(profile, relative_path)` returns a path only for a member of that verified receipt; a tree output resolves to its immutable directory. The worker receives no CAS path and cannot supply one.

The receipt producer and root fact inspector are implemented behind typed interfaces, but registration remains disabled until the managed terminal build runner and root-managed CPython probe are composed in the authority runtime. No ARM64 build or target execution has been performed here. HW-T03, CPython ABI acceptance, Colibri runtime qualification, Coral delegate use, and hardware acceptance remain open. GLM-5.2 weights are not build outputs and this path does not download them.
