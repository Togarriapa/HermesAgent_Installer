# Local board, voice and web plugin adapters

`components/plugin_local_voice_web.py` contains three installer-owned implementations for the preserved `epic-kanban`, `voice-pipeline`, and `web` Plugin identities. They are executable only when the selected-adapter registry supplies typed services from the protected host runtime. Plugin YAML and tool arguments never select service implementations or credential values.

The local Kanban adapter accepts the board store already bound to one protected profile. It exposes bounded create/read/item-update/delete operations, restricts item types and workflow states to the manifest, and delegates deletion to a store operation that must require an accepted completion summary and a done board. Its service must use an installer-owned per-profile root and ephemeral lifecycle. GitHub Projects v2 remains a separate account-enrolled adapter; repository and issue mutation are not part of this implementation.

The Wyoming adapter accepts only explicitly configured loopback or named local endpoints. Microphone bytes come only from the injected trusted current-session capture service after its session permission check; audio is bounded, held for the local STT call, and discarded. Piper output is bounded and sent to the current session playback service. No background capture, cloud fallback, audio persistence, wake-word authority, or Home Assistant mutation is provided. The host runtime currently has no enrolled microphone/audio bridge or selected Wyoming endpoint, so operational voice use remains unavailable until those services exist and pass target qualification.

The web plugin never opens a network connection. It submits a canonical web.retrieve action to the protected plugin effect dispatcher. A root-side plugin.web.read handler requires the one-use grant and exact enrolled profile, target, generation, recipient and payload digest; it then authorizes the URL against the finite task target list. The root HTTPS reader accepts only one public HTTPS GET hop on port 443, enforces a one MiB response and deadline, resolves and rejects private/reserved DNS results before connecting to the selected numeric IP, validates TLS hostname/certificate, disables all proxy use, and returns 3xx responses without following them. The root handler validates each redirect before the next hop. It emits an untrusted source receipt with URL chain, response digest, connected IP, certificate digest, enrollment and generation. Search, authenticated actions, credential submission and arbitrary HTTP methods are not implemented. The host runtime has no protected plugin effect enrollment/binder, so live web reads remain unavailable.

Fixture evidence: `tests/contracts/test_plugin_local_voice_web.py` exercises local board lifecycle and invalid fields, session permission and synthetic voice data, plus HTTPS redirect, transport, private-address and size denials. These fixtures verify adapter behavior only; they do not establish microphone, Wyoming, network, account, or target operation.

The concrete local backends are in `plugin_kanban_store.py`, `plugin_public_https.py`, and `plugin_wyoming.py`. The board store uses the installer's `OwnedRoot`, a profile-specific SQLite file and accepted-completion verifier; after acceptance it keeps a digest-linked completion summary and deletes the active board. Tests use temporary owned roots and a synthetic verifier.

The HTTPS reader in plugin_public_https.py disables proxies by using a direct numeric-address socket path, rejects any DNS answer outside public unicast space before connecting, connects to the checked address, validates TLS hostname/certificate with the platform trust store, and returns one hop without following redirects. It caps the response and records URL, body digest, connected IP, certificate digest, status, redirect chain, enrollment, generation and retrieval time in a reproducible source receipt. PluginWebReadEffectHandler is a root-side handler and must be registered only behind AuthorityService's one-use RB08 effect rule. Tests mock DNS/socket/TLS; they make no network request. Plugin tool code only calls the protected action dispatcher and has no reader object.

The local Wyoming client implements the current event framing, bounds PCM and generated output, pins numeric local endpoints from root enrollment, and gives each operation one deadline. The injected session bridge supplies microphone bytes only from an authorized active session and sends playback only to that same session. STT uses 16 kHz/16-bit/mono PCM; Piper output is pinned to 22.05 kHz/16-bit/mono. Tests cover synthetic PCM/events and session leases without opening sockets or recording a microphone.

The protected plugin effect contract is tracked in the Sol-owned RB08 ledger. Root must enroll the exact fixed target and generation and bind each tool invocation to its finite action schema before these backends are exposed. Until that binder and the Pi-local services are observed, these implementations remain fixture-qualified only.

Wyoming packet and request event shapes follow the [OHF-Voice Wyoming protocol](https://github.com/OHF-Voice/wyoming/blob/main/README.md).
