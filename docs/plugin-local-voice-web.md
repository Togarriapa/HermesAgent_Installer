# Local board, voice and web plugin adapters

`components/plugin_local_voice_web.py` contains three installer-owned implementations for the preserved `epic-kanban`, `voice-pipeline`, and `web` Plugin identities. They are executable only when the selected-adapter registry supplies typed services from the protected host runtime. Plugin YAML and tool arguments never select service implementations or credential values.

The Kanban tool sends each fixed board operation through the root-selected `.plugin_effects.invoke` boundary (`create`, `read`, `add_item`, `move_item`, `delete_accepted`). The root handler owns the per-profile SQLite store, acceptance verifier and one-use grants; the tool receives no store/path handle. Create/add/move/delete require committed effects, and delete requires the root lifecycle attestation plus all board items done. GitHub Projects v2 remains a separate account-enrolled adapter; repository and issue mutation are not part of this implementation.

Each voice tool makes exactly one root-selected action call (`voice_transcribe` or `voice_speak`) using a pinned finite argument-schema variant (`voice-transcribe-session-workflow-v1` or `voice-speak-session-workflow-v1`). The root owns the fixed session open/capture/STT/close or open/TTS/close workflow, current permission, fresh child grants, bounded in-memory audio lifetime, local Wyoming endpoints and output playback. Native handlers never call child steps or handle raw microphone bytes. No background capture, disk audio persistence, cloud fallback, wake-word authority, or Home Assistant mutation is provided. Operational voice remains unavailable until exact workflow artifacts, action bindings, permission observers and target qualification are present.

The web plugin never opens a network connection. It submits a canonical `retrieve` action through `.plugin_effects.invoke`. A root-side `plugin.web.read` handler requires the one-use grant and exact enrolled profile, target, generation, recipient and payload digest; it then authorizes the URL against the finite task target list. The root HTTPS reader accepts only one public HTTPS GET hop on port 443, enforces a one MiB response and deadline, resolves and rejects private/reserved DNS results before connecting to the selected numeric IP, validates TLS hostname/certificate, disables all proxy use, and returns 3xx responses without following them. The root handler validates each redirect before the next hop. It emits an untrusted source receipt with URL chain, response digest, connected IP, certificate digest, enrollment and generation. Search, authenticated actions, credential submission and arbitrary HTTP methods are not implemented. Live web reads remain unavailable until the root effect binder and target enrollment are observed.

Fixture evidence: `tests/contracts/test_plugin_local_voice_web.py` exercises fixed root action mapping, fail-closed missing resolver behavior, invalid board fields, one-call mock voice workflow actions and exact schema variants, plus HTTPS redirect and private-address denials. These fixtures verify adapter behavior only; they do not establish microphone, Wyoming, network, account, or target operation.

The concrete local backends are in `plugin_kanban_store.py`, `plugin_public_https.py`, and `plugin_wyoming.py`. The board store uses the installer's `OwnedRoot`, a profile-specific SQLite file and accepted-completion verifier; after acceptance it keeps a digest-linked completion summary and deletes the active board. Tests use temporary owned roots and a synthetic verifier.

The HTTPS reader in plugin_public_https.py disables proxies by using a direct numeric-address socket path, rejects any DNS answer outside public unicast space before connecting, connects to the checked address, validates TLS hostname/certificate with the platform trust store, and returns one hop without following redirects. It caps the response and records URL, body digest, connected IP, certificate digest, status, redirect chain, enrollment, generation and retrieval time in a reproducible source receipt. PluginWebReadEffectHandler is a root-side handler and must be registered only behind AuthorityService's one-use RB08 effect rule. Tests mock DNS/socket/TLS; they make no network request. Plugin tool code only calls the protected action dispatcher and has no reader object.

The local Wyoming client implements the current event framing, bounds PCM and generated output, pins numeric local endpoints from root enrollment, and gives each operation one deadline. The injected session bridge supplies microphone bytes only from an authorized active session and sends playback only to that same session. STT uses 16 kHz/16-bit/mono PCM; Piper output is pinned to 22.05 kHz/16-bit/mono. Tests cover synthetic PCM/events and session leases without opening sockets or recording a microphone.

The protected plugin effect contract is tracked in the Sol-owned RB08 ledger. Root must enroll the exact fixed target and generation and bind each tool invocation to its finite action schema before these backends are exposed. Until that binder and the Pi-local services are observed, these implementations remain fixture-qualified only.

`plugin_channel_provenance.py` provides separate HTTP and local-audio `native-input` producer callbacks for the v40 channel enrollment. The protected HTTP observer must verify the actual root listener record, JWT/principal mapping, live session/revocation, exact body schema, body digest and controller/service generation. The audio observer must verify the selected device/backend, current session permission and explicit consent, sealed capture artifact, format and bounds. Each producer accepts only the proof object returned by that observer, revalidates it for the source issuer, and binds it to the selected enrollment; neither producer creates proof handles or accepts a caller `authorized` flag. HTTP event bytes are strict-JSON parsed and canonicalized after matching the hash of original request bytes. Audio source events contain only an owned artifact reference and receipt fields, never microphone bytes. These interfaces do not establish actual HTTP/JWT account setup or microphone/session consent; native target qualification remains pending.

Wyoming packet and request event shapes follow the [OHF-Voice Wyoming protocol](https://github.com/OHF-Voice/wyoming/blob/main/README.md).
