# HI08 native Hermes boundary overlay

`native_boundary_patch.py` builds a separate overlay for the three reviewed files from the exact Hermes source pin `7085fbf7753266fc4943c55ac04926186bc90005`. It verifies full-file SHA-256 preimages and every patch anchor before creating output, refuses drift or preexisting changed output, and verifies generated bytes are non-writable. The pristine source checkout is never edited. The machine-readable record is `runtime_patches/hermes-agent-7085fbf/native-boundary-v1.json`.

The overlay captures the complete canonical JSON SDK request envelope immediately before observed primary OpenAI-compatible and Codex calls and before each patched auxiliary completion attempt. It also captures a tool-result message before appending it to the transcript. Provider attempts use HI11 v2's root `prepare_native_event(payload, parent_receipt_handles, purpose, intent_id, trace_id, retry_index)` producer method, which captures those exact bytes and returns a fresh opaque `X-Hermes-Installer-Context` bridge handle. The boundary also sends the bounded decimal retry index in `X-Hermes-Installer-Retry-Index`; it is untrusted transport metadata, and the root must compare it with the index stored on the opaque handle. The worker cannot provide event kind, origin, PID, sensitivity, public status, gateway identity, or receipt identity. Existing caller-supplied request headers are rejected; the boundary adds only the host-issued bridge reference and root-derived retry metadata. Source ancestry is retained, while event, context, and effect grants are single-use. Authority absence, unsupported request bodies, missing bridge API, malformed handles, expired leases, and preparation errors stop dispatch before the SDK call. Direct primary Anthropic, Bedrock and MoA paths are denied because they do not pass through this enrolled gateway boundary.

Before dispatch, the adapter clamps the SDK timeout to the root-issued event lease. The pinned primary request client already disables SDK-internal retries; the overlay now forces this for patched auxiliary OpenAI clients too, so every retry reaches a Hermes call site and obtains a new root event. The adapter identifies a retry only when the next attempt has the exact same canonical SDK envelope. It increments the retry index for that unchanged envelope and keeps the same intent/trace IDs. A changed envelope starts a new intent with retry index zero; it does not assert a worker-selected retry relationship. Upstream fallback chains that mutate model/body therefore still need explicit host retry admission before they can be considered covered.

The earlier `capture_source` API establishes only a host-observed private/unknown byte snapshot associated with an enrolled process; it is not a cross-process bearer. HI11 v2 defines the required separate `dispatch_native_request(handle, normalized_payload, retry_index)` gateway RPC: the root authenticates the enrolled gateway process, compares the exact normalized payload digest to its protected canonicalization, resolves the complete source closure, and consumes the bridge while internally performing the fixed provider effect. That API and the actual producer/gateway UID, executable, profile, generation, and enrollment mapping are not yet present in this worktree. Until the paired identities and single-RPC root effect are implemented and installed, provider egress through this overlay must remain unavailable.

This patch does not inject trusted runtime context into upstream `PluginContext.register(ctx)`. It does not cover all native provider modes, memory/background/delegation sources, direct effect-broker bypasses, or public-clearance issuance. Native profiles are not a process/filesystem sandbox. The tests for this overlay establish only patch integrity, Python compilation, and adapter fail-closed behavior. They are not native Pi acceptance, do not verify installed runtime behavior, and do not close HI-T08.
