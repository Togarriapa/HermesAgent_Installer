# Acceptance evidence

[Current scope](../requirements/current-scope.json) defines every functional requirement, component alias, current task and AC01..18. All acceptance is OPEN until exact-candidate proof qualifies it. Implementation, configuration, authentication, discovery, functional operation, enablement and actual target acceptance remain separate states. Source/readme/inventory/clone/process health or one chat cannot prove full installer, Resources, model, hardware or account acceptance.

Record exact candidate SHA, actual target/runtime/account boundary, UTC observation time, bounded redacted command/effect summary, actual positive/denial/recovery assertions and digest of privately retained evidence. Fixture, native ARM64, physical Pi and account evidence are distinct. No self-reported JSON boolean authenticates an actual effect. The enrolled protected verifier must authenticate the retained artifact, custody and target provenance before aggregation trusts a pass. Missing/skipped/truncated/unimplemented evidence stays pending; observed failures remain visible.

Root-side candidate/admission/result registries bind current protected enrollment, service generation/principal, actual platform and selected fixed workflow. Native effect or account authorization must be checked at the real boundary. A profile/home name, caller lease, dataclass instance or structural request/result ingestion cannot grant authority. Fixed CLI parser/adapter presence is not evidence that the full target workflow is composed.

AC01..12 cover fresh install/adoption/idempotence/failure/update/recovery/registry policy/core/provider/GLM/Coral/MCP/memory/individual integration effects. AC13..15 cover owned secure Cloudflare setup, finite Jarvis owner access and active expiry/revocation. AC16 covers full Resources/native materialization and dispatch; AC17 fresh protected Access membership/revocation; AC18 root host/process custody and actual native isolation/dispatch mediation. Hardware/account lanes need their actual authorized objects and effects.

All tests/fixtures/previews/validators and actual probes run only on the identified Pi through root browser. Do not copy secrets/raw environment/private prompts into evidence. Current [factual reports](evidence/) describe their exact candidates and boundaries, never qualify a later candidate automatically. Full release/finished docs follows actual end-to-end review, not a planning checkbox or fixture summary.
