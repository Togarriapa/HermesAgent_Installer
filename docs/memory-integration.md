# Memory provider integration

Memory records are owned by one capture provider per profile. Hermes continues to own conversation coordination; the installer injects the guarded per-profile HERMES_HOME and separately supervises each provider's service/data directory. Changing owner must flush and stop the former capture stream before selecting the new one. Retrieval may select a compatible provider, but never makes it a second automatic capture owner.

The adapters in `src/hermes_installer/memory/providers.py` address only opaque host broker targets. They contain no HTTP transport, endpoint, credential-file lookup, or process launcher. The root-owned broker enrolls fixed target IDs and translates each provider operation to the pinned native API. Agent Memory targets its selected rohitg00/agentmemory source; its upstream export endpoint is not namespace-scoped, so the broker must bind it to the profile's isolated service/data root before enabling export or delete. OpenViking and claude-mem workers must already be running under host custody before `doctor` can succeed. Their native setup paths never run from a Hermes hook.

Capture receives a signed source HostContext. Extraction and embedding are separate effects, each with a new host-issued context derived from the source lineage and each requiring their own protected target and capability. The adapter persists facts only after both effects succeed. A missing broker, grant, service handler, embedding route, or valid response fails closed before persistence. Provider retries and queued hooks must acquire fresh contexts and grants for each attempt; caller labels and saved grants are not authority.

A broker-fixture contract verifies payload digests, fixed target IDs, distinct extraction/embedding/capture grants, namespace filtering, and recursion rejection. Fixture success is not service, sandbox, account, native hook, or hardware acceptance. Live acceptance remains pending until a root-owned broker with peer-credential checks and protected handlers is installed, all private operations are routed through it, supervised provider services pass the pinned native API checks, and synthetic data survives a real service restart and fresh Hermes session. Backup, restore, deletion, and disablement must use the same profile-owned journal and broker scope.
