# Root Resources controller runtime

`RootControllerRoleRuntime.from_root_runtime` is the production constructor for the selected cron, webhook, and channel dispatcher roles. It accepts the active `RootRuntimeBindings` role rows, the typed `ProtectedEnrollment` and selected resource/job registries, a current `VerifiedInstallerReleaseReceipt` plus `RootActorObservation`, and the actual `SystemdMainPidInspector`. It verifies that the selected unit MainPID is the current root actor, pins daemon executables through the active artifact catalog and protected staging root, and reads role module source only through the installed release receipt's no-follow artifact-ID FD. The selected role module must be an immutable installed module member with the exact enrolled SHA.

The constructor loads and registers modules inside the current root service process, then builds the active role resolver and a typed static ingress selector from protected source issuer, observer, resource, and backend rows. The selected static registration ID comes from the protected resource job's `schedule_or_route_id`; it is not an event or receipt ID. Producers obtain a typed binding through `resolve_selected_ingress_binding(role_id, issuer_id, backend_id)` before event capture, then obtain live PIDFD custody through `resolve_selected_ingress_controller(...)`. The actual `RootResourceControllerRegistry` attaches once with `attach_event_registry` after that registry is assembled. Role/event proof use rechecks current PIDFD, systemd unit, executable, loaded module state, generation, and lease. `close()` detaches the event registry and revokes all modules and held ingress proofs for that generation; the surrounding root service retains and closes the release receipt and actor observation.

This constructor is unavailable on non-Linux development hosts and does not establish target acceptance. The Docker/systemd root fixture remains the positive host-kernel test path.
