# Root-selected native plugin binding status

The HI08/HI09 source-context requirements are in `planning/native-host-service-contract.json`. Sol's detailed native package binding contract is being merged separately; this worker-side resolver projection is implemented in `hermes_installer.native_plugin_bindings` against that proposed wire. The contract is not a claim that an Authority RPC or runtime loader is installed.

The planned plugin-loader binding uses only the no-argument `bind_selected_native_package()` and `read_native_resolver(opaque_binding_handle)` queries. Root selects exactly one active package using the authenticated peer process, profile and generation; zero or ambiguous selection fails. The response is a short-lived same-peer binding handle and a canonical resolver document whose SHA-256 is checked locally. Caller paths, `PYTHONPATH`, user site-packages, profile plugin directories, resource YAML, environment identity variables, and dynamic import locations never select code.

Resolver rows are immutable presentation metadata. They identify the selected adapter/action, manifest and adapter digests, argument/result schema IDs, effect enrollment, operation, capability, target, recipient and generation. A selected row is not a grant. The root must independently re-resolve current enrollment, schema, source lineage, identity, recipient and one-use effect authorization on every invocation. The intended local facade is `plugin_effects.invoke(adapter_id, action_id, arguments, idempotency_key=None, opaque_confirmation_attestation_id=None)`; no credential value, arbitrary endpoint, shell, URL, path, profile, role or caller-supplied capability enters it.

The resolver DTO does not import plugin code. Native code must come only from the root-selected compiled closure and its pinned dependency catalog, after custody verifies the complete immutable tree and mounts it read-only into the enrolled service's private mount namespace. Package mount IDs are root-owned identifiers, never request paths. This worktree does not yet contain the mounted closure or Authority binder/resolver RPCs, and custody confirms there is no package closure mount API. Role-specific source issuers and a trusted Hermes loader injection are also absent. Therefore no native plugin is enabled by this adapter. The loader must remain unavailable until those integrations exist and exact package hashes and source/result event roles are verified.

Generic worker `capture_source` is explicitly retired. Tool, memory, effect, child, schedule and authenticated user-input receipts require the corresponding root-observed issuer. In particular, tool output supplied by a worker is not evidence of a real tool result, and unknown input remains private/ineligible for public routing. Fixture tests for the DTO parser do not prove root enrollment, package mount integrity, native loading, role provenance, or target acceptance.
