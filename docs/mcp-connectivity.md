# MCP connectivity

MCP initialization, tool discovery and calls run through fixed read-only broker handlers with bounded deadlines. The worker sends a canonical service/tool/selection intent; the host verifies its exact grant, binds the service to root-owned enrollment, and resolves the endpoint and credentials outside worker config. Unknown schemas, revoked credentials and missing account eligibility fail closed. Selected-resource adapters narrow tools to reviewed harmless reads and return results through privacy policy.

Figma and RevenueCat have fixed official HTTPS endpoint bindings in the root broker catalog, but require a protected service/account enrollment, credential custody and selected resource before use. Google official MCP services remain unavailable until preview eligibility is verified and a service/resource is selected. The taylorwilsdon option is a separately labeled community server and remains unavailable until exact source, executable and per-tool effect review is enrolled. Home Assistant's endpoint and exposed-entity set are instance-specific; no endpoint is currently enrolled, and setup does not create or replace HA. Playwright remains unavailable until a pinned package and live supervisor lease are enrolled. A profile is not an OS sandbox; process/network isolation remains dependent on host custody enrollment and Pi verification.

Fixture success does not establish live account authentication, external reachability, ARM64 browser support or selected-resource verification. Setup performs no message, document/calendar, Figma, RevenueCat or Home Assistant mutations.


Google Workspace endpoints and effect classifications were checked against Google's primary [setup guide](https://developers.google.com/workspace/guides/configure-mcp-servers) and per-tool references: [Gmail](https://developers.google.com/workspace/gmail/api/reference/mcp), [Drive](https://developers.google.com/workspace/drive/api/reference/mcp), [Docs](https://developers.google.com/workspace/docs/api/reference/mcp), [Sheets](https://developers.google.com/workspace/sheets/api/reference/mcp), [Calendar](https://developers.google.com/workspace/calendar/api/v3/reference/mcp), and [People](https://developers.google.com/people/api/mcp). These services require Developer Preview program membership, a Cloud project, and the relevant Workspace API and MCP API enabled. The service catalog pins every Google endpoint to the official setup guide, including Docs and Sheets at their documented `/mcp/v1` routes. The client selector keys match the documented JSON input fields (for example `messageId`, `fileId`, `spreadsheetId`, `calendarId`). The People profile tool is not exposed because it has no selected-resource parameter; contact search is bounded to the exact selected query. No caller-provided boolean establishes eligibility. The protected host currently has no signed account-eligibility claim, so Google MCP calls remain unavailable until that enrollment evidence exists and OAuth is verified.


The native Hermes `mcp_servers` config merge is storage-only and does not mediate tool calls. The root-selected config writer stores protected HTTPS endpoint metadata with the selected MCP tool allowlist and keeps direct Hermes transport disabled; actual calls are exposed through the pinned in-process native hook and fixed root authority dispatch. Credentials remain root-held opaque vault references and are never copied into `config.yaml`.

For the native tool path, `service_generations.native_mcp_tool_bindings` and `native_schema_artifacts` are the protected registration/schema sources. Schema bytes must be canonical, digest-pinned and joined to a current source receipt and selected package/action before a candidate is compiled. The registration index resolves only an exact Hermes tool name and canonical argument-schema digest that joins the selected profile/process generation, native package, MCP enrollment, selected resource reference, request/result schemas, fixed effect rule and pinned handler artifact. A name/schema mismatch, stale generation, unknown tool, missing selected-resource reference or conflicting caller scope stays unavailable before broker I/O. The selected profile config writer preserves unrelated user settings and commits only root-derived disabled metadata; no caller-proposed server map, endpoint, credential or filesystem path is accepted.

When the source-pinned in-process hook is integrated, its handler will rely on the root-observed one-use Hermes tool binding. The worker will submit only its opaque invocation handle and canonical arguments to `native.mcp.dispatch`; root will re-resolve the current name/schema/service/resource join, validate the request schema and selected-resource scope, obtain a fresh `mcp.request` or `mcp.stdio` grant, and perform the effect through the protected transport and vault. Root will validate and privacy-scrub the result before returning it to Hermes. The intended path has no worker-selected service, endpoint, credential or resource ID. Account eligibility, selected resource enrollment, active root tool mappings, the pinned handler artifact, config materialization and native ARM64/Pi behavior remain prerequisites for enablement.

Root authority assembly uses `build_enrolled_mcp_handlers` from `hermes_installer.mcp.enrolled_transport`. It accepts immutable protected service records plus host-loaded `ProtectedMCPHTTPBinding` records; the handler factory validates the service ID, reviewed revision, exact endpoint and primary-source URL, and requires an opaque custody credential handle. It registers only HTTP services in the compiled official endpoint catalog. It does not accept a worker URL, command, or secret. Stdio services are omitted until a live managed-process lease adapter is available. An empty enrollment produces no MCP effect handlers, so discovery or catalog presence does not imply availability.

The HTTP broker preserves its Streamable HTTP session per enrolled profile, verifies the host effect grant before dispatch, enforces a single aggregate monotonic request deadline, and cancels the active coroutine when the grant expires, the caller disconnects, or the request is cancelled. Integration tests and host enrollment are required before any external functional claim.
