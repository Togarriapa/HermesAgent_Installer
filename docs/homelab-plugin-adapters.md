# Homelab plugin effect adapters

The reviewed adapter code in `src/hermes_installer/components/plugin_homelab.py` corresponds to the pinned `HermesAgent_Resources` 2.3.1 plugin manifests `authentik-authorization@1.0.0`, `cloudflare-homelab@1.0.0`, and `homelab-ops-broker@1.0.0`. Imported metadata selects the plugin identity only. The adapter provides its own schemas and fixed action names.

Every tool call asks the root `AuthorityClient` to classify trusted Hermes invocation lineage, issue a payload-bound one-use grant, verify that grant, and perform the fixed effect. Writes use the root `host.write` operation, which applies a fresh Authentik `System` membership check before dispatch. Read operations use `provider.dispatch`. No plugin handler receives account tokens, host credentials, user-supplied principal claims, URLs, shell arguments, or filesystem paths.

The Cloudflare surface accepts only the three manifest hostnames and symbolic `ha`, `nc`, and `hr` tunnel identities. DNS targets are constrained to IP addresses or names under `togarriapahome.uk`; tunnel reconciliation carries only the selected tunnel and hostname, leaving ingress details in root enrollment. Operations use only `hermes` and `nextcloud` host aliases plus manifest-listed read/write verbs. Destructive broker verbs require a host-issued, one-shot confirmation reference. No raw SSH, shell, `occ`, Docker, systemd, or arbitrary operation interface exists.

These native handlers do not imply account or target enrollment. The current runtime has no protected Authentik read-only effect handler, no live System-recipient listing API, and no enrolled Cloudflare or host-operations effect handler for these plugin identities. Consequently the root must deny calls until the corresponding fixed `(operation, target)` rule, effect handler, vault references, and owned target records are installed. No account, DNS record, tunnel, Pi, or service has been contacted by these fixtures. A real handler must revalidate its root grant immediately before the side effect, preserve a durable operation journal, and reject any target that is not present in that root-owned enrollment.

The focused fixture suite is `tests/contracts/test_plugin_homelab.py`; it checks the actual registered schemas, typed payloads, fixed effect verbs, source identity/version binding, out-of-scope rejection, and pre-dispatch denial when fresh authorization fails. Passing fixtures is not evidence of an enrolled account, target, or live service.
