# Installed release stage-zero verification

The first setup command cannot use `root-setup-selection.json` as its trust source because that file is the output of the first setup publication. The installed root release is selected from the root deployment record at `/var/lib/hermes-installer/deployments/current.json`. The record is a root-owned, single-link regular file with mode `0600`; it selects only `/usr/lib/hermes-installer/releases/<candidate_git_sha>`. No caller-provided path or manifest is accepted.

The record pins the release directory device/inode, closure-manifest relative path and SHA-256, full frozen-plan tree SHA-256, and publication monotonic time. The closure manifest is root-owned mode `0444`, schema 1, and binds the candidate Git SHA to a sorted unique list of portable relative file paths, SHA-256, size, mode, and finite role labels. The verifier opens through held directory descriptors with `O_NOFOLLOW`, checks every file and parent, rejects symlinks/hardlinks/special files/unlisted content, and verifies the complete closure before issuing a process-local receipt.

The frozen baseline is checked in two domains. `plans/2026-10-09-v1/hashes.json` retains its 160-file repository-relative snapshot map, which is checked against the corresponding bytes under the baseline directory. Separately, the full tree SHA is SHA-256 over canonical compact UTF-8 JSON of every regular file under that directory, keyed by its baseline-relative path and including `hashes.json` and metadata. It is not the Git tree SHA-1.

The v30 compiler template is required at its fixed artifact ID/path/hash. The installed actor verifier binds the actual launcher and interpreter, current PIDFD and `/proc` start time, real UID/GID, namespace inode identities, imported installer module origins, sanitized isolated Python search paths, and current release file hashes. The receipt and actor observation remain in-process root-only objects; they are not RPC payloads and do not assert a selected service principal or generation.

`InstalledRootReleaseVerifier.from_current_root_process()` is the supported entry point. It is intentionally unavailable on non-Linux or outside the real root process, and remains unavailable until the root deployment stage has written a valid current receipt and complete immutable release. Fixture tests validate parser/path/custody failures; they do not establish a target installation or Pi acceptance.
