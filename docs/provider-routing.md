# Provider routing and account eligibility

Provider use is opt-in and fails closed. The default additional metered budget is zero. A model catalog, the `:free` suffix, source configuration, or a credential reference does not establish account entitlement or effective account privacy settings.

## Dispatch boundary

Synthetic transport fixtures use the shared Dispatcher to exercise route, token, tool, sensitivity, retry and aggregate-budget behavior. Production native Hermes requests use the HI11 atomic bridge described below; the old worker context-factory/Dispatcher handoff cannot authorize production provider traffic. Unknown prices and private work without a root-authorized private-capable route remain unavailable. Paid calls require a deliberately configured positive aggregate budget, reserve spend before the network request, reconcile usage conservatively, and keep reservations for ambiguous failures.

The production native path is moving to HI11's single atomic bridge call. A host-enrolled Hermes producer prepares an event from the complete SDK request bytes and trusted source closure; the gateway passes only that opaque event handle and its final normalized request to `dispatch_native_request`. Authority authenticates the gateway process, verifies and consumes the one-use event, derives route/capability from the canonical bytes, and performs the fixed provider effect in one IPC. An event handle alone is not authority. The earlier worker `context`/`authorize_effect`/`verify_effect` sequence is fixture-only for native traffic; do not use it as a substitute for the atomic bridge. Every retry requires a fresh producer event and corresponding retry index. Missing host issuer, bridge, protected enrollment, source closure or eligible route leaves inference unavailable.

Retries are bounded, cancellation-aware and deadline-limited. Retry-After is clamped. Fallback routes are explicit policy entries and must satisfy the same model, sensitivity, capability, price and budget checks. Provider-side fallback, plugins, compression and unreviewed transforms are disabled in the public OpenRouter request.

## OpenRouter Nemotron

The pinned public route is `nvidia/nemotron-3-ultra-550b-a55b:free` at the fixed OpenRouter endpoint. HI11 now requires the root-selected `provider-output-reject-4096-v1` policy record: canonicalizer artifact SHA and the separate seven-field policy SHA are checked independently; the same record controls producer normalization, gateway normalization, and the final handler. Values above its 4096 ceiling and combined output aliases are rejected. SIWC uses its separate `siwc-output-unsupported-v1` policy and continues to reject `max_output_tokens`. The adapter requires current authoritative account-policy evidence before resolving the key or opening a network client. Evidence binds the model, private credential reference, credential fingerprint, account-policy snapshot and expiry. Synthetic eligibility evidence is accepted only by opted-in test fixtures. The fixed root handler factory now binds the selected policy with target/recipient, principal, model, credential scope, payload digest, retry and sensitivity, then requires a fresh protected admission immediately before egress. Production still has no configured account admission or host-vault enrollment, so the service does not register this handler and OpenRouter inference remains unavailable until account, model, zero-price, endpoint and effective processing-policy eligibility are proven.

The host target identity is `provider://openrouter/api/v1/chat/completions?model=nvidia%2Fnemotron-3-ultra-550b-a55b%3Afree`; it is an enrolled broker identifier, never a caller-supplied URL. The public route accepts text and ordinary function tools only. `OpenRouterLiveAdmission` is a root-injected, per-attempt check for the account’s current key status and exact model price/modality/limits using the documented [current-key endpoint](https://openrouter.ai/docs/api/api-reference/api-keys/get-current-key) and [model details endpoint](https://openrouter.ai/docs/api/api-reference/models/get-model). It fails closed unless the key reports free-tier status and the exact model remains text-only with zero prompt/completion price. This still does not verify an account’s effective data-retention settings, prove entitlement to private data, or replace a completed account-specific inference/tool canary; the host must register a protected admission before any provider handler is created. Image/audio/video inputs, hosted/server-side tools, flat (non-namespaced) function tools, caller-selected plugins, model overrides and fallback lists are rejected; only bounded direct function tools grouped in SIWC-supported namespaces are accepted. OpenRouter currently lists the free variant at $0 input/output, 1M context, and 65,536 maximum completion tokens; it supports function `tools` and `tool_choice`, but not `response_format`. The endpoint says not to submit confidential or personal data and describes usage logging for NVIDIA service improvement. Catalog pricing and model support do not prove account entitlement or account-specific privacy settings ([model entry](https://openrouter.ai/nvidia/nemotron-3-ultra-550b-a55b:free)). Do not send private Google or Home Assistant content, private repositories, personal memory, tool results, system context or derived summaries to this route.

## Codex and Claude

Codex subscription sign-in and separately billed OpenAI API keys are distinct. `openai_auth.ChatGPTPlanAuth` implements the public-client Sign in with ChatGPT code+PKCE flow behind injected host-brokered HTTP, ID-token verification and host-vault interfaces. It binds a stable host ID and per-account issued client ID, checks state/nonce/audience/issuer/subject and requires the returned `chatgpt.tokens.use.direct` scope before storing credentials in the injected vault. Refresh is serialized per account and retains rotating token pairs together. Sign-out discovers and validates the issuer's revocation endpoint, attempts refresh-token revocation, clears local tokens, and keeps the account/client mapping; its result distinguishes confirmed remote revocation from local-only sign-out. It never writes OAuth tokens into Hermes profiles. This is functional OAuth contract code; no account has been enrolled here.

The branch implements the documented wire contract in `CodexResponsesTransport`: normalized input arrays, `store:false`, `stream:true`, rejection of unsupported fields and roles, and bounded SSE parsing that accepts success only after `response.completed`. Its native-event entrypoint hands the normalized request to HI11 in one atomic broker call. Synthetic contract fixtures cover completion, failure, incomplete responses, malformed/partial streams and unsupported inputs. See OpenAI’s [Models and inference guide](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference), [current preview limitations](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations), and [Sign in with ChatGPT guide](https://developers.openai.com/siwc/token-sharing-open-source/sign-in).

This protocol implementation does not enable the route. No ChatGPT account is enrolled; there is no protected account-specific model-list/entitlement admission or completed live inference canary. The native Hermes request issuer and complete primary/auxiliary/tool/memory/background lineage resolver are also absent, so a loopback context header or a private/unknown source receipt cannot authorize provider dispatch. Keep Codex unavailable until those independent gates are integrated and proved. API-key billing remains a separate metered route.

The root `provider_effect_handlers.build_provider_handlers()` and synthetic effect tests are only implementation fixtures. Production still lacks an enrolled ChatGPT account/provider admission, published HI11 client methods, the per-request native event issuer, a validated root credential scope and Hermes-native route injection. A transport header may carry an opaque lookup handle, but it cannot authorize provider dispatch by itself; Authority must authenticate the native process and gateway peer, preserve complete parent lineage and atomically consume the prepared event. Do not pass caller receipt IDs or labels as evidence. No account is enrolled and no inference canary has been run, so Codex inference remains unavailable. OpenAI API keys are a separate metered route requiring an explicitly configured aggregate budget.

Keep Claude Free in the account inventory. Current Claude Code documentation lists paid plans and other named eligibility paths, not the consumer Free tier ([Claude Code authentication](https://code.claude.com/docs/en/authentication)). A consumer login alone does not prove Claude Code, Anthropic API, or third-party inference eligibility. If a supported account path cannot be verified, automatic Claude inference is unavailable. Do not extract browser cookies or bridge the consumer web session to an API.

## OmniRoute

The source adapter verifies the explicit OmniRoute `3.8.52` commit and root package lock, stages it into a private writable workspace, and describes fixed offline `npm ci --ignore-scripts` and backend-build invocations. `prepare_omniroute_build` submits these stages only through the injected installer-owned managed component supervisor, requires structured zero-exit evidence for each, and skips the backend build after dependency failure. It selects the protected component Node `26.7.0` Linux ARM64 catalog artifact, whose pinned upstream engine hash is `afc7a004…50090d`; Node `20.19` is rejected. This is an implementation/runtime recipe, not evidence that those bytes, ARM64 native dependencies, or a built service have passed on the Pi. Build output remains pending native qualification.

`OmniRouteGatewayAdapter` is the one-request HI11 integration seam: it normalizes a request against a root-selected exact route, rejects caller fallback/provider/route/compression overrides, and calls the authority's atomic `dispatch_native_request` once. This normalization is not fresh entitlement evidence; the root handler must repeat account, price, privacy and budget admission immediately before egress. The adapter never receives provider credentials or performs direct network I/O. Its synthetic recording-bridge test proves only this adapter contract; it is not an invocation of the upstream OmniRoute service. The service invocation builder binds to loopback, keeps API key reveal and cloud sync disabled, carries no credential references, and requests host `provider-dispatch` mediation. It stays unavailable when the protected service/effect profile or exact route is missing.

Upstream OmniRoute advertises a broad provider catalog, automatic fallback, and request compression. Those behaviors cannot be trusted as policy enforcement. Only one public-only, exact zero-budget model route is currently representable; private, paid, fallback, retry, compression, and plugin routes are rejected. Root-enrolled OpenRouter account/model/privacy admission, complete HI11 native producer/gateway integration, validated upstream service configuration, and actual ARM64 install/build/service effect proof are still missing. Keep the feature disabled until the host egress profile can prove those upstream behaviors cannot bypass the broker and the native tests pass. Source download/configuration is not service enablement.

## Evidence status

Contract fixtures demonstrate policy behavior against synthetic transports and synthetic account proof. They do not establish external account entitlement, live provider terms, actual account-level privacy settings, host process/filesystem isolation, or live Pi inference. Account, model, provider service, and target acceptance must be recorded separately with fresh evidence. No user credential or external account is enrolled by this code.
