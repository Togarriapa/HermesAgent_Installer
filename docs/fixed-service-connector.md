# Fixed local service connector

HI07 implementation is provided by `hermes_installer.service_connector`. The protected root daemon owns the TCP socket and returns only a bounded JSON stream receipt with an opaque connector handle, service generation, monotonic expiry, and fixed frame limits. The HI13 gateway-side `ServiceConnectorClient` accepts only a root-issued remote session handle; `.open()` takes no caller-selected route, and the returned typed stream offers synchronous `read(maximum_bytes)`, `write(data_bytes)`, and `close()` methods through the authenticated authority API.

The only routes in the source catalog are `xpra-native/xpra-http`, `xpra-native/xpra-websocket`, and `colibri-main/colibri-openai-v1`. Root resolves each exact enrollment, profile, target, route, and generation to a registered live process handle, then enters its protected network namespace and connects to the fixed loopback endpoint. Callers cannot provide a process ID, address, URL, port, namespace selector, or socket descriptor. Service namespace and process PIDFD leases remain root-owned for the stream lifetime.

Open, read, write, and close use separate one-use authority grants against the same exact target ID. Open binds enrollment, generation, route, session, action and deadline in the canonical body; grant/context metadata remains outside the digest. Every stream call binds the peer UID/PID, source-lineage hash, route, target, session, frame sequence and fresh operation grant. Frames are limited to 1 MiB; a stream is limited to 16 MiB and 60 seconds. The watchdog closes both directions and releases the retained process/namespace lease at expiry or shutdown. A stale generation, exited process, peer/session mismatch, replay, arbitrary route, cancellation, exhausted budget or stream-capacity denial occurs before additional socket bytes are relayed.

The root connector enforces the application routes before forwarding bytes: Xpra accepts one `GET` or `HEAD` request for a path in the pinned HTML5 asset manifest, strips caller headers and rebuilds fixed loopback headers; its WebSocket handshake fixes `/` and the `binary` subprotocol, then permits only complete binary data frames. Colibri accepts one unauthenticated JSON `POST /v1/chat/completions`; health, arbitrary API paths, cookies, and authorization headers are denied. The gateway still applies JWT, Access policy, origin and active-lease checks before invoking this root connector. Memory compounds and MCP endpoints are not registered by the raw stream connector; each requires its own typed root protocol. This does not establish native Desktop acceptance.

The prior caller-context client is not an admission path for Xpra or Colibri. Those targets remain unavailable unless root has the HI13 JWT and current-policy verifier bridge; it derives principal, token fingerprint, profile, route, generation and lease from the verified remote session, then issues fresh operation-bound grants internally. A browser or gateway-supplied principal, policy grant, URL, port or route never authorizes the root connector.

`build_remote_service_connector_backend(catalog, process_manager, validate_binding, ...)` provides the HI13 root transport adapter. It requires an explicit coordinator-owned current-binding validator and resolves the exact protected route through the shared process manager. It does not return an AuthorityService caller-context handler map. Daemon registration remains unavailable until the root remote-session coordinator wires this backend and its per-frame grant callback.

`tests/contracts/test_service_connector.py` uses a local TCP listener to verify an actual open/write/read effect, plus unknown-route, stale-generation and foreign-peer denials. These tests are fixture evidence; protected root daemon installation, Linux namespace/cgroup effect tests, gateway protocol restrictions, and ARM64/Pi service acceptance remain separate and pending until their respective evidence jobs pass.
