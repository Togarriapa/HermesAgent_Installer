# Protected artifact and package broker

The host authority loads `/etc/hermes-installer/artifact-catalog.json` as a protected installer-owned mode-0600 file and builds fixed handlers with staging root `/var/lib/hermes-installer/artifacts`. The catalog and staging directories must not be writable by profiles or other untrusted principals. `load_protected_catalog` rejects symlinked/non-regular files, unsafe ownership or mode, duplicate JSON keys, unknown fields, unsupported URLs, invalid digests, and invalid bounds. The authority process must run as its enrolled installer UID.

A caller sends only `artifact_id`, catalog SHA-256 and `max_bytes`; it cannot choose a URL or path. The handler binds those fields to the signed one-use grant, checks cancellation and the monotonic lease, revalidates the current authority policy immediately before opening the network connection, and checks cancellation/deadline again. It fetches from the catalog HTTPS URL with certificate verification, no inherited proxy, and catalog-allowlisted redirect hosts, then verifies stream size and digest. Interrupted transfers keep a private partial file and resume only while the grant remains live. Completed bytes are fsynced and atomically renamed to a content-addressed, read-only file. The receipt contains an opaque `artifact:<id>:<sha256>` store ID, digest and size; it contains no bytes, URL, credential or filesystem path.

`ArtifactCatalog.resolve_store_id(store_id, staging_root, expected_uid=0)` resolves only that enrolled object after checking ownership, regular-file type, write bits, byte limits and a fresh SHA-256. `materialize_store_id(...)` additionally extracts an enrolled archive into a protected immutable tree and compares every path, digest, size, executable bit and enrolled symlink target. Tar gzip and tar xz archives are supported. Absolute, escaping, cyclic, dangling, special-file, or parent-symlink-conflicting entries are rejected. The result exposes `path`, `sha256`, `tree_files` and a canonical `tree_manifest_sha256`; caller-side work should use a private writable copy when a build tool needs to edit source.

The reviewed seed catalog pins the Hermes installer at source commit `7085fbf7753266fc4943c55ac04926186bc90005`, that commit's PM lock, and the PM-declared Linux ARM64 Python 3.14.7, uv 0.12.3 and Node 26.7.0 artifacts. It also includes the exact Colibri source archive and the reviewed Coral CPython 3.9.25 source, TFLite 2.14.0 and NumPy 1.26.4 wheels, and official compiled sample model. Archive rows contain complete per-file manifests; direct wheels and model bytes remain separately digest-pinned. These rows authorize only fixed-ID retrieval/materialization, not successful runtime installation, component operation, or hardware qualification. The Coral Python 3.9 source is EOL, and the target's native ABI/delegate requirements still gate enablement.

Current Python package records refer to one specific ZIP wheelhouse, runtime identity, protected interpreter and versioned installation root. The manifest allows only exact `name==version` requirements carrying SHA-256 hashes. Installation runs fixed venv creation and offline pip with `--no-index`, `--no-deps`, `--only-binary`, and `--require-hashes`, using sanitized environment and bounded cancellation. It does not offer arbitrary shell, caller-supplied commands, or package-index access. Separately cataloged Coral wheels are not yet an installable package set: a protected multi-wheel package/runtime enrollment and built component-owned CPython 3.9 runtime are still required. No direct profile pip path or constructed unreviewed wheelhouse is allowed.

Catalog JSON uses schema 1 with exact top-level keys `schema`, `artifacts`, and `packages`. Artifact rows have `artifact_id`, `version`, `sha256`, `source_url`, `max_bytes`, `size_bytes`, `redirect_hosts`, `filename`, `tree_files`, `archive_format`, `archive_root`, and `max_tree_bytes`. Tree rows contain `path`, `sha256`, `size_bytes`, `executable`, `kind`, and `link_target`; legacy regular-file rows with the original four fields remain accepted. `archive_root` is null or an exact normalized tar directory prefix ending in `/`. Package rows have `package_id`, `version`, `artifact_id`, `artifact_sha256`, `runtime_id`, `python_executable`, `environment_root`, and `install_timeout_seconds`. The protected file limit is 16 MiB to accommodate reviewed complete file manifests.

Implementation evidence is covered by OpenSpec `host-principal-custody` HI01/HI-T01 and `installer-bootstrap-desktop` BD-F01, with lifecycle recovery LC-F01 as a prerequisite. The catalog remains inert until root daemon assembly enrolls the fixed catalog/staging paths and passes the root-only policy revalidation callback; no live target has been installed or accepted by this adapter.
