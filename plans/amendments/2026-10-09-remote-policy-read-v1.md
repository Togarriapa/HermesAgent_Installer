## Why and scope

R0206 requires bounded current authorization, but Cloudflare documents that policy identity is reevaluated at policy-session expiry. A valid JWT delivered through a fresh protected HTTP request alone is not proof of out-of-band policy membership. R0209 permits gateway only necessary nonsecret configuration and makes management token setup-only. Therefore the separate minimum-read credential is an additive deployment requirement implementing existing safety, not an implicit grant to retain setup secrets in runtime. Read authority must reside in a separate isolated privileged-by-credential verifier; the browser-facing gateway stays nonsecret. No runtime code is changed here.

The user authorizes automatic owned Cloudflare setup, blank hostname, emailOTP and secure token collection. Continue automatically with supplied scoped refs; ask only missing credential/configuration or genuine ambiguity. Do not collect secrets in chat or introduce another approval workflow. Do not assume ability to mint read tokens using setup token or request token-admin grants. A separately supplied minimum-read token/reference is mandatory when current authority cannot otherwise be proven; missing authority is incomplete, not a temporary usable60-second mode.

## Requirements, tasks and evidence

- **RP01 (Separate read credential enrollment), RP-T01:** The installer SHALL securely collect or resolve a distinct account-scoped minimum-read Access credential for an isolated policy verifier, independently of the setup-management token and tunnel credential. It SHALL keep blank hostname and automatic owned setup, request only genuinely missing fields, and report configure-later/incomplete when the read authority is unavailable.
  Evidence EV-RP01: WHEN only setup-management token is supplied, THEN owned setup can checkpoint, but remote activation and session issue remain incomplete with exact read-reference resume field; no management-token runtime fallback.
- **RP02 (Isolated verifier credential custody), RP-T02:** A dedicated least-privilege verifier SHALL hold the read credential in protected host custody. Desktop, cloudflared and the browser-facing gateway SHALL receive no setup/read secret or resolver; gateway receives only authenticated, narrowly scoped decision messages. The verifier SHALL perform fixed GET requests for journal-selected account/app/policy/OTP identity and SHALL expose no generic API proxy or mutation operation.
  Evidence EV-RP02: WHEN a compromised gateway requests another account, arbitrary URL, write method or secret dump, THEN verifier rejects before network effects; OS identity/socket/filesystem/process controls prevent credential reading; secret canaries absent from argv/environment/logs/repr/profile/evidence.
- **RP03 (Fresh exact Access membership authority), RP-T03:** Before initial authorization, socket opening and each separate protected-HTTP renewal, the verifier SHALL freshly read the exact owned app, complete bounded app-policy set and selected identity-provider resource, match sole intended OTP IdP, exact hostname and explicit email policy with no broadened/unsupported rules, and deny errors, conflicts, missing pages, unsupported policy semantics or stale observations. Valid JWT signatures and a fresh HTTP request alone SHALL not establish current policy membership.
  Evidence EV-RP03: WHEN a still-valid JWT is presented after allowed-email removal, extra policy addition, IdP replacement or read failure, THEN no new grant or lease extension occurs; the previous bounded lease expires without fallback; malformed/order-only policy responses are interpreted with explicit safe semantics.
- **RP04 (Bounded freshness and cancellable read decisions), RP-T04:** Each verifier request SHALL have a hard total deadline at most9 seconds including bounded TLS reads/pages/retries, bounded workers/queue and cancellation that cannot leave accumulating secret-bearing tasks. Decisions SHALL be single-use, bound to authenticated peer/principal/app/config/nonce and monotonic observation interval. Lease deadline SHALL be no later than read-start+60 seconds or JWT expiry; watchdog SHALL stop input/output within5 seconds of the deadline. Late results SHALL never renew expired/cancelled sessions.
  Evidence EV-RP04: WHEN a renewal read hangs or completes9 seconds after a policy removal concurrent with the read, THEN existing lease is not extended while waiting; pending operation is bounded and discarded on timeout/cancel; read latency does not add to60-second authorization age; no accumulating threads or replayed allow.
- **RP05 (Read-role lifecycle and secret preservation), RP-T05:** Setup SHALL retain management credential only in secure setup custody and SHALL never mint API tokens using assumed administrator grants. Read credential rotation/expiry/revocation, disable, restart, update, backup/restore and uninstall SHALL preserve ownership, securely reference credentials, invalidate old decisions and fail closed until current authority is verified. Uninstall SHALL remove only owned local credential artifacts, never revoke or delete unowned account tokens/resources.
  Evidence EV-RP05: WHEN restored configuration names a missing/expired read reference or verifier service stops, THEN remote remains incomplete, all leases stop at their existing deadlines or earlier, no setup-secret promotion or plaintext backup leak; resumable secure rotation and fresh validation required.
- **RP06 (Distinct revocation evidence and readiness), RP-T06:** Verification SHALL distinguish policy/email removal, local logout, Cloudflare application/user token revocation, JWT expiry, read-token revocation and verifier/network outage. A policy read SHALL not be claimed to prove JWT/token revocation. Remote readiness SHALL require actual production verifier custody and transport plus signed-JWT/HTTP/WS tests and exact-target/account evidence for AC15; no usable-by-default60-second shortcut.
  Evidence EV-RP06: WHEN policy-removal fixture passes but Cloudflare token-revoke behavior has not been observed, THEN policy enforcement evidence is recorded separately; token/logout revocation acceptance stays pending rather than inferred or waived; live bounds identify event timing and provider visibility.

## Implementable custody and timing contract

Use dedicated unprivileged verifier service with credential privilege, isolated from native Desktop/Xpra/cloudflared/gateway UIDs, profiles and writable files; protected host-owned credential reference/file (0600 owner,0700 ancestors, no symlink/path escape), secure local IPC peer authentication. Gateway sends typed principal/application/session nonce/config digest; verifier returns bounded nonsecret one-use grant/deny with observation interval, not token/API dump. Verifier owns bounded TLS transport, fixed API GET allowlist, full capped pagination/response sizes and minimal environment/no proxy inheritance. No generic HTTP relay, shell, shared writable module path, or secret resolver in gateway. Existing7a90f5 FreshAccessPolicyAuthority is partial implementation evidence, not production custody: callback running in gateway would violate this contract; asyncio.to_thread timeout does not cancel a blocking task. Implement actual bounded worker/process cancellation and reap on timeout without accumulating tasks.

Fresh read must include exact app/hostname/AUD binding, sole selected OTP IdP resource and exact explicit approved-email policy set; extra policies, unsupported rules, ambiguous/reused identity changes deny. Normalize order/case only with defined safe equivalence, not false whole-account trust. Complete current membership must be recomputed each decision; no cached allow. Requests/results bound to config generation, session and authenticated principal; old rotation/restore/generation replies cannot authorize new session.

Total read deadline<=9s. Do not add read latency to lease age: lease end<=minimum(read-start+60s,JWT expiry); monotonic clock tracks deadlines, wall clock only verified JWT expiry with bounded conversion. Previous lease continues to its original end while renewal waits; no frame after expiry. Watchdog<=5s. If policy changes immediately after a read begins, a9s read cannot yield a fresh60s extension from its completion; subtract observation latency or deny. Bound queue/workers, cap all API pages/retries within total deadline; cancellation/timeout must discard late replies, reap workers and never block stream watchdog. Multi-GET is not an atomic Cloudflare snapshot: detect inconsistent IDs/versions and fail closed, and measure policy visibility/TOCTOU interval honestly.

## Lifecycle and preservation

Read role is local owned credential custody only; secure refs/redacted metadata in journals/backups, no plaintext token export. Stop/disable invalidates local authority and leases; rotation/restart/update/restore require fresh exact checks before activation, clear cached decisions and old nonce keys. Missing or revoked ref remains incomplete with automatic secure resume. Uninstall removes only owned local artifacts, never deletes/revokes a preexisting user API token or shared OTP provider. Setup management token remains secure setup-only; cloudflared retains dedicated protected token-file, Desktop/gateway never receives either API credential. No automatic new spend/account privilege escalation.

Prior Resources amendment remains: actual739 tracked files in installer, all eight roots and helpers, self-contained owned source update/repair/restore after upstream deletion; no regression to download dependency. This focused amendment does not change Resources runtime.
