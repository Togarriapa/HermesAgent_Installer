# Compatibility and evidence limits

The target is Raspberry Pi5 with nominal16GB RAM,1TB SSD and optional Coral USB or PCIe/M.2, running supported 64-bit Linux ARM64. Actual OS/glibc/systemd/filesystem/storage/ports/device facts must be measured. The installer is under development; [current scope](requirements/current-scope.json) separates code and target/account acceptance.

| Area | Current required path | Evidence limit |
| --- | --- | --- |
| Official Hermes | pinned headless core, official PM-managed Python3.14, protected loopback owned service | Existing selected Pi private core/chat is distinct from fresh-install qualification |
| Jarvis | finite authenticated responsive web client; Cloudflare Access OTP/binding | Public route, concurrency, expiry/revocation/restart need exact current proof |
| Graphical software | Desktop/Xpra excluded from installation; source is capability benchmark only | Owned cleanup waits for protected replacement proof; shared dependencies preserved |
| Installer/components | isolated typed Python orchestration and component-specific runtimes | No global Python downgrade or unreviewed lazy install |
| Providers/accounts | supported subscription/API auth; explicit eligibility, modality, privacy and zero metered budget | Login/catalog pricing is not account inference/tool entitlement or paid-processing denial |
| GLM-5.2 / Colibri | required exact artifact, native ARM64 engine and bounded measured experimental service | No replacement model passes; no huge download implied; resource/performance acceptance OPEN |
| Coral | detected USB/PCIe/M.2; isolated supported runtime and actual compiled-model delegate inference | Device enumeration is insufficient; no LLM acceleration claim |
| Full Resources | all208 source identities and actual individual native discovery/delegated dispatch | Materialization/definition inventory does not prove functional enablement |
| Skills/plugins/MCP/memory/apps | complete licensed source/assets and harmless selected-resource effect tests; one automatic memory owner | Account/native dependency/actual operation distinct; per-item acceptance remains open until proof |
| Browser/voice/mobile | retained sandbox/TLS, owner grants, real keyboard; explicit microphone/device/account limits | Native wake/hotkey/background behavior cannot be promised from web feasibility |
| Development tooling | pinned OpenSpec1.14.1 with supported node runtime | Tests/fixtures/previews/validators only on identified Pi via root browser |

Unsupported architecture/license/account/modality/authorization yields unavailable with exact next action; it never silently drops functional scope. Family conversation ownership is not filesystem/tool/global-memory isolation. HA live configuration remains deferred. Preserve host timezone; new schedules/display times default Europe/Lisbon. No spend, reimage/format, unrelated service replacement or outbound test messages are implied.

Experimental GLM thresholds require recorded measured values before claiming suitability: warm TTFT<=30s, generation>=1token/s, core-chat p95<=10s under auxiliary load and no OOM/throttle failure. They are acceptance targets, not demonstrated Pi performance.
